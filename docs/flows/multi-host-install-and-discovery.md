# Multi-Host Install and Discovery

## Purpose

Get the Coder Squad Core artifacts (`AGENTS.md`, `agents/`, `commands/`, `skills/`) discovered by a specific AI coding tool ("host") in that host's own native format, without hardcoding the host list anywhere in the agnostic core.

## Trigger

A user runs `adapters/install.sh install [<host>] [--dry-run] [--force]`, or a host's plugin marketplace resolves `.claude-plugin/`, `.cursor-plugin/`, or `gemini-extension.json` directly.

## Participants

- `registries/hosts.json` -- the host-adapter registry (single source of truth for which hosts exist and what each one surfaces).
- `adapters/install.sh` / `install.ps1` / `link.sh` -- the installer (reads the registry; contains no hardcoded host list).
- `scripts/gen-manifests.py` -- generates the seven per-host plugin manifests under `adapters/manifests/<host>/` from `VERSION` + on-disk inventory + the registries.
- The discovery-path symlinks at the repo root (`.claude-plugin/`, `.cursor-plugin/`, `gemini-extension.json`, `plugin.json`, `marketplace.json`) -- where each host's plugin-marketplace mechanism looks first.
- The target host's config directory (e.g. `~/.claude`, `~/.config/opencode`).

## Step-by-step flow

1. **Registry lookup.** The installer reads `registries/hosts.json` and, for each adapter entry (or the one named on the command line), resolves `config_dir`, `config_file`, and which of `skills` / `commands` / `agents` that host's `surfaces` object turns on.
2. **Doctrine link.** `AGENTS.md` is symlinked into the host's config dir under that host's `config_file` name (e.g. `CLAUDE.md`, `GEMINI.md`, or `AGENTS.md` verbatim for hosts that already use that filename).
3. **Skills link.** If `surfaces.skills` is true, the whole `skills/` directory is symlinked in -- each skill stays in its native nested `skills/<name>/SKILL.md` form.
4. **Commands link.** If `surfaces.commands` is true, `commands/` is symlinked in as `commands/` -- flat `<name>.md` files, native to opencode/kilo/Claude Code.
5. **Agents link.** If `surfaces.agents` is true, `agents/` is symlinked in under that host's `agents_path` (e.g. `agents/` for opencode and Claude Code, `agent/` -- singular -- for kilo).
6. **Existing-link check.** Before writing any symlink, the installer distinguishes three cases: not yet installed (link it), already correctly linked (skip, log "already linked"), or STALE (points elsewhere, e.g. a pre-v3 path) -- STALE links are only replaced with `--force`, and a real (non-symlink) file at the target path is never clobbered.
7. **Marketplace path (alternative entry).** Independently of the installer, a host's plugin-marketplace mechanism (Claude Code, Cursor, Gemini CLI) resolves the repo root's discovery-path symlinks, which point into `adapters/manifests/<host>/` -- content generated by `scripts/gen-manifests.py` from the same registry plus on-disk inventory.

## Data and state changes

No repo state changes during install -- only symlinks are created/removed in the *target host's* config directory (outside this repo). Regenerating manifests (`python3 scripts/gen-manifests.py`) rewrites `adapters/manifests/<host>/*.json` in place from `VERSION` + on-disk inventory + the registries.

## Success behavior

Every artifact the host's `surfaces` flags turn on is reachable at the exact path that host's own documentation says it scans (verified against opencode, Claude Code, and kilo's published discovery paths). `adapters/install.sh status` reports every link as `OK`.

## Failure behavior

- A pre-v3 STALE symlink (e.g. pointing at a since-renamed path) is reported and left untouched unless `--force` is passed -- it is never silently overwritten.
- A real file already present at the target path is never clobbered; the installer reports it as a skip.
- `--dry-run` previews every action without writing anything.

## External dependencies

`python3` (used by `install.sh` to parse `registries/hosts.json`; no other runtime dependency). `install.ps1` uses PowerShell's native `ConvertFrom-Json`.

## Invariants and assumptions

- No host name, host config-dir path, or host config filename is hardcoded anywhere under `AGENTS.md`, `agents/`, `commands/`, or the seven core skills -- that would violate `G17_agnostic_core`. All host-specific data lives in `registries/hosts.json` or under `adapters/`.
- `commands/` (plural) and `agents/` are always linked as flat directories of `<name>.md` files -- never reshaped per host. `skills/` is always linked nested (`<name>/SKILL.md`).

## Security and privacy notes

Symlinks are created only inside the invoking user's own config directories (`config_dir` values are user-home-relative). No credentials or secrets are read or written by the installer itself.

## Observability and debugging

`adapters/install.sh status [<host>]` reports the link state (`OK`, `STALE`, `not installed`, or `REAL-FILE`) for every artifact at every adapter. `adapters/install.sh list` prints the resolved adapter table straight from the registry, useful for confirming the registry parsed as expected.

## Testing notes

`scripts/checks.py` gate `G16_registries_parse` validates `registries/hosts.json` structurally (non-empty `adapters` list, required keys per adapter, unique `code` values). `G13_plugin_symlinks` validates the discovery-path symlinks resolve into `adapters/manifests/<host>/`. `G15_manifests_generated` fails if a checked-in manifest drifts from what `scripts/gen-manifests.py` would produce.
